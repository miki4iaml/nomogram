# AGENTS.md — nomogram

Rules shared by all contributors and their coding agents, whatever the
tool. The practical guide (setup, hooks, commands, pull request
workflow, releasing, the rationale of settled decisions) is in
[.github/CONTRIBUTING.md](.github/CONTRIBUTING.md).

## Project

`nomogram` is a repository of scientific formulas. It references
formulas and manages their alternative notations (by author,
publication, domain convention), the units of their parameters —
including empirical ones —, their validity domains, their LaTeX
rendering and their use in symbolic computation.

Reference use case: list the alternative formulations of air humidity
HA = f(T, RH), compare them, plot them.

Structural constraint: the package must work on an offline workstation.
It may rely on well-supported, widely adopted dependencies, but never on
a conversion or rendering engine reachable only through the Internet
(no CDN-hosted MathJax, no online converter, no remote ontology at run
time).

## Design goals

Five goals guide development. Each is a rule for every entry, enforced
by the invariants below, the loader and the tests; `python -m
nomogram.catalog stats` prints indicators of how far the catalogue
covers each. They are goals, not comparisons with other tools.

1. **Alternatives side by side**: every formulation computes a quantity
   kind, so the alternatives for one quantity are found together
   (`Catalog.formulations_of`, `search(kind=...)`).
2. **Validity, scale and sources stated, never invented**: validity
   domains, conventional scales and reference statuses follow the
   catalog invariant below.
3. **Open, machine-readable data**: the catalogue is TOML under
   BSD-3-Clause, in a documented, versioned format
   ([docs/catalog.md](docs/catalog.md)); the vocabularies it bundles
   keep their own licences ([data notice](src/nomogram/data/NOTICE.md)).
4. **One source for every output**: the expression is the only source
   of a formula's mathematics (invariant below); every extension of the
   model, such as piecewise definitions or new functions, goes through
   it.
5. **Linked to shared vocabularies**: every quantity kind is a QUDT kind
   or specializes one, which the loader checks; CF standard names and
   Wikidata items are linked where an equivalent exists, with their SKOS
   relation and date of verification.

## Architecture and invariants

- Core dependencies: `sympy` (formula expressions, LaTeX, symbolic
  computation, `lambdify`), `numpy` (vectorised evaluation) and `pint`
  (units, the engine shared with MetPy and xarray). `matplotlib` is the
  `[viz]` extra (xarray's name for it), imported lazily inside
  `nomogram.plot`, with an explicit message if it is missing.
  Development and CI install all extras.
- `import nomogram` stays light: submodules (`nomogram.units`,
  `nomogram.expression`…) are imported on demand.
- A formula's mathematical content is written once, as an expression in
  restricted Python syntax. It is parsed with `ast` against a whitelist
  into a SymPy expression, never with `eval`, `sympy.parse_expr` or
  `sympify`, in the package or its tests: a ruff rule (`TID251`) refuses
  them, and an exception carries a justified `# noqa: TID251`, seen in
  review (as is `sympy.S` applied to a string, which the rule cannot
  tell from `sympy.S.One`). LaTeX (per notation), numeric functions and
  symbolic results all derive from it; nothing is duplicated by hand.
- Units: nomogram's own pint registry, created once and never modified;
  pint's global registry is never touched. Celsius temperatures are
  points of an interval scale (`degC`); differences use `delta_degC` or
  `K` (SI Brochure, 9th edition, section 2.3.1). Unit symbols are those
  of the SI Brochure (the unit one is 1, rarely written); a unit outside
  the SI keeps QUDT's symbol unless the source of a formulation writes it
  otherwise. Departures from QUDT are declared in the extraction script.
- Vocabulary: QUDT terms first (quantity kind, quantity value, unit,
  scale type…); any other term is justified by a dependency's or a
  standard's usage. [docs/rosetta.md](docs/rosetta.md) maps the terms
  across QUDT, the SI, pint, SymPy, CF and OM, and lists ambiguous
  trade terms; keep it up to date when a concept is added. A kind
  specializes another only when its values can feed every input of the
  other; a look-alike gets a sibling kind, and each meaning of a trade
  term points to the quantity its source defines, never to a kind that
  only shares the term. A kind is neutral as to the medium (air, sea
  water) unless the medium is part of the quantity
  ([docs/catalog.md](docs/catalog.md)).
- Semantics: quantity kinds, unit definitions and CF standard names come
  from frozen QUDT and CF subsets in `src/nomogram/data/semantics.json`,
  generated by `scripts/extract_semantics.py` (rdflib, development
  only), never edited by hand, and re-extracted before each minor
  version (see CONTRIBUTING, Releasing). What nomogram adds to the sources
  (scale typing, added units, pint expressions) is declared in that
  script. Links to external vocabularies are `ExternalMatch` objects
  (SKOS relation, date of last verification), held only by the object
  they identify.
- Catalog: formulations are hand-written TOML in
  `src/nomogram/data/catalog/`, validated when loaded. Details not
  checked against the source carry `status = "to-confirm"`. Validity
  domains are objective only (physical, or stated by the source with its
  criterion); coefficients of fixed-units formulations are never
  converted. Temperature inputs record the scale the formulation was
  fitted on when it is known (stated, inferred from the date only, or
  inferred from numbers); inputs are taken on ITS-90 and
  converted to it before evaluation.
- Reference data is immutable (`frozen=True`, no mutation after
  construction); no mutable global state, so that the package is safe in
  concurrent contexts (parallelism is the caller's business); symbolic →
  numeric conversions, costly and deterministic, are cached
  (`functools.lru_cache`).
- Explicit public API (`__all__`). Only the public API is covered by
  semantic versioning.

## Conventions

- Language: English for everything versioned (code, docstrings,
  documentation, commits, pull requests). French translations:
  `README.fr.md`, `.github/CONTRIBUTING.fr.md`, and later the
  documentation; the English version is authoritative.
- Branches: `main` (released versions), `develop` (default branch,
  integration), and work branches prefixed with their Conventional
  Commits type (`feature/`, `fix/`, `docs/`…). Never commit directly to
  `main` or `develop`: always a branch, then a pull request.
- Merges into `develop` are squash merges only; the pull request title
  becomes the commit message.
- Commit messages and pull request titles: Conventional Commits
  v1.0.0, optional scope, ASCII-only subject.
- Commits signed and verified by GitHub, required on every pull
  request.
- Versions: `0.x` until a `1.0.0` whose scope is still to be defined.
  Version declared only in `pyproject.toml`, read through
  `importlib.metadata`. Git tags prefixed with `v`.
- `requires-python = ">=3.12"`. Development on 3.12.
- Documentation: Sphinx, NumPy-style docstrings. A strict build will
  be a blocking CI check.
- License BSD-3-Clause. Every source file starts with the two lines
  `# SPDX-FileCopyrightText: 2026 Miki` and
  `# SPDX-License-Identifier: BSD-3-Clause`.

## Releasing

Read [CONTRIBUTING, Releasing](.github/CONTRIBUTING.md#releasing)
before preparing a release, and follow its steps in order. Never publish
a GitHub release just to test: each published release also archives a
permanent Zenodo DOI; the rehearsal described there publishes to
TestPyPI instead.

## Security

No safety rule is bypassed, including during project bootstrap.

- GitHub Actions pinned by commit SHA, never by a moving tag; the
  repository enforces it. Dependabot keeps the pins up to date.
- Workflow permissions read-only by default; elevated only in the job
  that needs it.
- No secret in the repository, no stored token: PyPI publication
  through OIDC trusted publishing.
- Local checks (pre-commit hooks): formatting, lint, secrets,
  anonymity and hidden characters before each commit; typing and tests
  on push. CI replays the same checks.
- Instruction files of coding agents are code. AGENTS.md lives at the
  root only; no other tool's instruction file, and nothing that stays
  local (`_priv/`, `.claude/`, `CLAUDE.md`, `.mcp.json`), is tracked;
  `scripts/check_integrity.py` refuses them, with hidden characters.
  A pull request from someone else is read as a diff (`gh pr diff`),
  never checked out in a working tree where a coding agent runs, which
  would load its instructions.
- Nothing personal or internal in what is published: no legal name,
  no internal path, no work email address, no customer name.

## Working rules

- Propose a plan before any change touching more than two files.
- Every new concept, field or section states how the search API reaches
  it: a search field, names added to the index, links between entries
  (`_references` in `nomogram.catalog`). `docs/search.md` stays up to
  date.
- Figures in the documentation use the presets of `DisplayOptions`:
  the code shown passes only what is the example's own, such as the
  limits of the axes;
  the rest of the formatting stays in the script that draws the figure.
  A setting several figures need becomes an option or a preset; an
  example showing an option sets it.
- No new dependency without explicit approval.
- The lowest supported versions of the dependencies are a goal, not a
  constraint: when keeping one would cost complexity, readability,
  maintainability or many more tests, propose raising it, stating why
  (its release date; SPEC 0 drops core packages two years after their
  release; who still needs it), and record it in `CHANGELOG.md`.
- No public function without a test.
- Every user-visible change adds an entry under `[Unreleased]` in
  `CHANGELOG.md` (Keep a Changelog format).
- No new file at the repository root unless necessary.
- Portability: `pathlib`, explicit UTF-8 encoding on every file open,
  no hard-coded shell command, `importlib.resources` for embedded
  data.
- No tool attribution in commit messages or pull request descriptions
  (no Co-Authored-By, no "Generated with …"); the policy on coding
  agents is in CONTRIBUTING.
- Propose before executing anything hard to reverse or
  outward-facing.
- Verify before asserting: a version or a tool behavior can be
  checked.
- Challenge a false premise rather than answering beside the point.

## Settled decisions

Not to be undone without discussion; their rationale is in
[CONTRIBUTING, Settled decisions](.github/CONTRIBUTING.md#settled-decisions).

- **CI matrix**: complete and blocking, Ubuntu and Windows × Python
  3.12 and 3.13; never aligned with a heavier repository's for
  uniformity.
- **Contributor signatures**: the `signatures` CI job requires every
  commit of a pull request to be signed and verified.
- **`.vscode` partly versioned**: only `settings.json`,
  `extensions.json` and `tasks.json`; never set
  `python.defaultInterpreterPath`.
- **mypy at pre-push** as well as in CI, deliberately.
- **Coverage**: branch coverage by coverage.py (no pytest-cov), 80 %
  floor in every cell of the CI matrix; CI is authoritative.
